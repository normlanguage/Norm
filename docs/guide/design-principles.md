# 设计原则

Norm 面向需要长期维护的应用软件。设计语言功能时，它优先考虑规则能否被稳定学习、代码行为能否从源码推断，以及不同功能组合后是否仍然简单。

## 1. 语义必须可预测

相同语法应在不同上下文中保持相同含义。

- 赋值默认复制值，不因类型来自库或框架而改变；
- nullable 只能通过 `?` 出现；
- 类型转换必须显式；
- 控制流表达式必须显式产生值；
- annotation 本身不能重写程序。

## 2. 默认值应该适合应用代码

Norm 选择非空默认和非共享默认，因为它们让局部修改更容易推理。

```norm
value Range {
    Integer start
    Integer end
}

Range visible = Range(start: 0, end: 80)
```

`Range` 没有 identity，也不需要共享。它只是一个值。

```norm
class Cursor {
    Integer position
}
```

`Cursor` 可以包含行为和可变状态，并且具有对象 identity。赋值会保留同一 cursor；需要新对象时显式调用 `copy()`。

## 3. 抽象服务于复用，不服务于炫技

接口和泛型用于表达稳定、可检查的复用关系。

```norm
interface Comparable<T> {
    Integer compareTo(T other)
}
```

Norm 不追求模板元编程或复杂类型级计算。抽象应该减少重复，同时保留可读的错误信息和调用方式。

## 4. 控制流不能隐藏

```norm
String parity = if number % 2 == 0 {
    break "even"
} else {
    break "odd"
}
```

这里的 `break` 不是多余字符，而是值流的明确标志。类似地，Result 不会用特殊运算符自动向上传播。

## 5. 语言、标准库和平台分层

Norm 文档把不同层次分开：

- 语言定义类型、值、函数和执行语义；
- 标准库提供字符串、集合、I/O、时间等通用能力；
- 应用平台提供 HTTP、数据库、配置和部署能力；
- 工具链负责构建、包管理、测试和发布。

框架示例不应承担解释基础语法的任务。学习者可以先完整理解语言，再选择是否进入某个应用领域。

## 6. 实现可以优化，语义不能漂移

运行时可以用写时复制、结构共享、逃逸分析和复制消除实现值语义。只要程序无法观察到与规范不同的结果，优化方式就是实现细节。

这也解释了为什么语言规范与官方 GraalVM/Truffle 后端保持独立：规范定义程序含义，后端只负责实现它。官方项目不因此维护第二套后端，第三方实现也不能改变语言语义。
