# 发布流程

Norm 目前处于语言规范草案阶段。发布物可能包含规范、参考解释器、编译器、标准库和工具链，它们必须使用同一个版本号与兼容性说明。

## 发布通道

- **nightly**：自动构建，允许不兼容实验，不承诺长期可用；
- **preview**：供语言功能试用，语法仍可调整；
- **stable**：规范与工具通过兼容性门槛后发布。

在首个 stable 版本之前，任何页面都不得把未实现功能描述成可下载产品。发布说明必须标出“仅规范”“部分实现”或“完整实现”。

## 发布步骤

1. 冻结目标 commit 和语言特性清单；
2. 运行 lexer、parser、类型系统、运行时和标准库测试；
3. 使用文档中的代码块执行编译测试；
4. 生成源码归档、平台二进制、校验和与 SBOM；
5. 签名发布物并发布版本说明；
6. 在独立干净环境验证安装与 Hello World。

## 版本说明

每次发布必须分别列出：新增语法、语义变化、诊断变化、标准库变化、迁移方式和已知限制。破坏性变化不能只写成“重构”或“改进”。

## 回滚与修复

构建错误或供应链问题允许撤下尚未广泛使用的发布物，但已经发布的版本号不重复使用。稳定分支只接受兼容修复；需要改变语言语义时发布新的 minor 或 major 版本。
